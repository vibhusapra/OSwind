## Canonical user-authored data

The backend introduced in `0c32217` adds `MemoryKind.recordingMetadata` (`recording-metadata`) within the existing canonical `memories` table. It uses the existing native source identity rather than adding a fourteenth canonical sync table. Names are separate user-authored records, not transcript edits or rebuildable-cache-only preferences. Naming preserves the audio IDs, original title/text/timestamps, recording ID and evidence hash. Session targets use exact UTF-8 recording IDs; legacy ungrouped targets use the same exact-evidence-version restriction as recording-scoped Ask.

Name snapshots have an open-store owner and an opaque metadata-row nonce. Editing compares the current snapshot inside a writer transaction and the current settings guard. Deletion/recreation, byte-distinct IDs, concurrent edits, changed/foreign audio and current privacy exclusions refuse stale edits. Multiple definitions are returned as a conflict; the edit API refuses to choose one by date or name. The selected-recording UI exposes each definition and allows confirmed removal of one reviewed name; it does not pick a winner.

`recorded_meeting_details` is a derived bounded metadata projection with built-in SQL triggers. It carries per-row revisions and joins the recording change nonce. Repair invalidates prepared metadata without scanning transcripts during installation; historical metadata rebuilding belongs to the later owned worker. Source-cache version 2 and canonical audio identity stay unchanged. Ready archive/revision/publication tests deny canonical payload reads and all SQL writes with a saved name present. The selected-name editing read hydrates canonical evidence only when a candidate name exists; a no-name result uses thin metadata and does not authorize a write. The selected detail and explicit-session sidebar display names. Legacy ungrouped exact-version labels are deliberately omitted from the thin archive summary until their evidence binding can be validated.

`RecordingCalendarLink` contains the exact occurrence identity, recurrence/date fields, reviewed revision and library binding. It copies no event title, attendees, description or join URL. It is data, not Calendar permission, proof of attendance or execution authority. The live provider/access/selection/library/privacy/source checks and historical resolver must be implemented before a user-facing link action.

## Selected editor in development

`RecordingNamesModel` owns selected-recording reads, saves and removal through the existing app work registry. The archive can select unnamed recordings without decoding their transcript to discover an absent label. Name publication uses a nonwaiting read-only revision/settings check. Every save/removal still validates canonical audio and the exact reviewed metadata snapshot in a writer transaction.

The editor preserves a draft when a concurrent edit is refused. A fresh review is required before Save becomes available again; the review flow keeps the proposed text and shows the newly read definition. Quiet archive refreshes retain that draft, while privacy/departure clears it and cancels its work. Multiple definitions appear in a bounded scrolling review area, with separately identified removal actions and confirmation. Removing a name preserves original audio; pending search/media cleanup remains visible.

## Typed transport in development

`SyncRecordingDetails` carries the source-origin session token or an exact audio wire-version reference. Imported clip IDs are remapped through the admitted canonical owner and retained original. Missing originals never select current text, similar titles or dates. Source graph admission, both original-evidence stores and retirement/peer erasure traverse the new exact reference; self-references and non-audio parents refuse. Incoming names require an already admitted audio owner. Causal delivery can queue a later name and replay both operations when the earlier audio arrives, without creating a source from a dependency body or echoing peer writes.

The optional field is absent from existing wire kinds, and metadata requires the new source subtype. Wrong kinds, missing details, captured assets and unknown details versions refuse. Calendar references remain bound data after transport, with no event contents or implied Calendar authorization. Both native-row and portable-body service policy scan calendar identifier strings for secret patterns as well as checking the authored name.

At source `e3bb845`, the temporary blanket transport refusal was removed, while unavailable or ambiguous exact originals still refused export. The current prototype below adds explicit unavailable projections. Durable affiliation through real rename now has selected controls. Recovery from actual retained originals and complete restored-catalog/session lifecycles remain open. A namespace or matching hash alone must never manufacture authority. This is not complete transport acceptance.

## Durable affiliation and canonical erasure

Commit `1c9bdaa` adds a bounded operational affiliation store, separate from the 13 canonical sync tables. It contains only the canonical metadata owner/lifetime, exact native scope, exact known wire reference or unavailable state, and a framed checksum. It stores no name, transcript or captured media. Native scope changes, owner deletion and replacement lifetimes invalidate it; accounting, rollback, reopen, schema integrity and a quiet restore with no copied operational authority have selected controls. Name and favorite edits preserve the exact reference while old private metadata wire bodies can still be purged. A known exact reference is retained through an unavailable projection, but returning to a matching hash cannot manufacture its missing body or owner authority. Policy, integrity, identity and cancellation failures propagate.

The earlier `c0668cb` proof worked only while the previous metadata projection remained cached. Its real-rename failure is retained; the durable cache fixes that control. Native transcript replacement intentionally purges its old cached audio body. Without an actual verified retained original, export becomes explicitly unavailable while preserving the authored native association and allowing unrelated publication. Actual retained-history recovery is still open.

Commit `bea65a9` adds ordinary local name erasure and known peer-name lifetime retirement. Four retained negative methods pass on that prototype, but two further controls expose destructive reliance on derived caches: a forged name-cache owner selects unrelated audio, and a missing session-cache member prematurely selects its name. The current fix uses SQLite-maintained expression indexes over canonical recording scopes and audio session IDs. A source erasure includes its names; a session name remains while an actual canonical member remains. Corrupt metadata projections are reconciled after deletion so stale private label text does not remain. Erasure does not hydrate an archive of transcripts. Existing audio archives defer building the session expression index until canonical session erasure needs it, inside the erasure worker's cancellable transaction. Naming and reopening a named archive do not build it. Fresh libraries maintain the index from their first audio row.

These controls cover known labels and canonical members. Late/concurrent unseen session names, complete session lifecycle semantics, combined sync/restore and the complete old sync-client matrix are not yet qualified. Calendar links remain dormant data without fresh local authorization and review.
