# Incoming entity graph — functional component verified

The internal typed adapter projects person, organization, project and place definitions; owned aliases; manual and peer automatic source links; name rejections; and stable project rejections. It adds content-free native deletion for these five canonical tables. No enrollment, transport, capture activation or public sync setting is enabled. F059 remains TODO.

## Admission and native behavior

The caller authenticates and journals one reviewed incoming head, holds the owning library media reservation before SQLite locks, and supplies current policy admission. Native mutations, global mappings, exact cached bytes, projection checks and journal receipts commit together. Policy refusal, a foreign/released reservation, a native key collision or a late dependency change rolls the operation back. Peer rows do not produce outgoing capture intents.

Entity lifetimes cannot change kind. Aliases have one owner within their kind; an incoming definition does not implicitly merge two people with the same name. Explicit same-kind merges can transfer an existing alias lifetime to its admitted destination. Alias and curated-project indexing bounds remain enforced. Native project rules are invalidated where matching changes. A peer automatic suggestion preserves its origin, exact source span and method; it never marks local extraction complete.

A link or rejection requires its exact source body and a current native source with the same entity revision. Text/title/app/URL/date/kind changes invalidate this relationship. A favorite-only source change can retain the old exact link. The final callback-free audit rechecks source revisions, current identity-only dependency heads, exact packets and the root projection.

## Schema 30 and ordering

The schema-29 source trigger could prune an independently live uncurated entity while another source or relationship awaited native projection. The new trigger preserves the independent definition only during the connection-scoped, exact incoming source write; it still clears stale links and corrections. Ordinary local edits and erasure retain their pruning rules. Current trigger protection is checked before general entity setup can recreate it.

Forty-five new writer guards fence old clients across thirteen canonical tables, historical evidence and run originals. A missing or altered current guard/source trigger refuses opening. Actual schema-29 migration is tested using a hash-pinned fixture created by the unchanged old CLI, with a note, manual entity link, stable project correction, cached wire versions and an imported run original. There is no fabricated version downgrade.

Outgoing work uses an indexed captured-sequence order. Relationship retirements precede replacement lifetimes within a batch; live alias transfers precede retirement of their former entity parent. One-object and 128-object merge tests include an earlier pending edit to the deleted entity. Selection uses `sync_work_sequence` without a temporary sort. The index is migrated atomically; a missing current index refuses opening.
