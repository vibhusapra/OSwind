# Audio import lifetime and current-settings admission

Audio-file import now owns its actual detached preparation, local speech and optional speaker work, file retention, database admission and actor completion through cancellation, wipe, Quit, library switch and encrypted-library lock.

## Behavior

The library work registry retains the worker through its real return. Cancel keeps the import busy while a local backend is still stopping. A canceled shutdown caller still joins the operation. Retired, closed and draining libraries reject a new import; late progress and completion cannot publish old-library status. Actual committed transcripts remain committed. Current postcommit cancellation explains that the transcript was saved and points to Conversations.

Audio decoding, source copying, embeddings and database admission execute off the main actor. The operation pins its normalized input and library media reservation through local speech, optional recording-local speaker annotation and actual admission. Privacy, clip retention and transcription/speaker settings revoke captured work before attempting settings persistence. Changing the independent Ask model does not cancel import.

Immediately before admission, the app captures its current settings and pins the saved settings-file identity. Saved privacy and retention must match the current choice. The Core configured path copies/embeds before SQL or settings locks, then owns an independent transaction and checks the saved settings version around its actual COMMIT. Replacement with identical settings bytes is still a different version and is rejected. An outer caller transaction is refused in configured mode so the version check cannot promise a commit it does not own. Existing callers without a snapshot retain their original contract.

Failed admission rolls back the new source and removes only its new retained copy, including cancellation from inside the actual SQLite insert. Cleanup uses the same descriptor, directory identity and no-symlink protections while deliberately ignoring cancellation for this narrow cleanup action. It preserves the input and unrelated retained recordings. Read-only and symlink-parent refusal remain tested. This does not prove physical power-loss recovery or general orphan-file collection.
