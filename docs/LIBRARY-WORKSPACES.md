# Library workspaces and explicit close

Schema 17 scopes supported library intermediates to private `audio/.staging` and `video/.staging` directories. This is preparation for an encrypted-library lifecycle, **not an encrypted vault implementation**. The installed app is unchanged until a tested build is packaged.

Live audio WAVs, app/CLI audio-import originals and normalized WAVs, Whisper output/log files for those operations, replay encoding/thumbnail files, backup source pins and Markdown source snapshots stay inside their owning library. Operation directories use existing descriptor-based private workspaces with ownership, path identity, leases and abandoned-job checks. Completed or cancelled operations remove their owned payload and companion lease files. The external original import file remains caller-owned.

Each workspace keeps a shared library reservation through model work, retention and admission. Full wipe and explicit close take an exclusive reservation before SQLite/store locks. They wait for cooperative operations rather than deleting an in-use temporary file. Audio admission borrows the workspace reservation and validates its library identity, avoiding a nested reservation while exclusive cleanup is waiting. A released or foreign reservation is rejected. Delayed audio/replay admission also rechecks the original library directory identity; failed audio cleanup uses its retained directory descriptor, so an alias redirected to another library does not redirect a copy or cleanup. Cancellation waits for an owned Whisper subprocess to exit before cleaning its workspace; termination escalates after two seconds for a child that ignores SIGTERM.

`MemoryStore.close()` cancels/disables new fast-index preparation, waits for reserved work, releases cached index readers and attempts `sqlite3_close`. An active SQLite statement returns a retryable error and leaves the connection available for reads and explicit close retry. Index preparation stays disabled on that connection after a close attempt; reopen to prepare it again. A successful close is idempotent and later database operations throw. It closes this store connection; independent external readers may still keep a volume busy. Finish/cancel an operation before calling close from its own synchronous callback, because that callback still owns a reservation.

A schema-16 staging prototype was tested against the actual old signed writer: with a held shared media reservation, one synthetic note and a sparse 2 GiB staging file, old retention deleted the note while trying to satisfy a 1 GB budget. Schema 17 therefore advances the database writer guard even though this layout adds no tables. Old binaries must refuse the new library; an already-open old process still needs to stop before upgrade.

History retention excludes known `.staging` subtrees from its budget calculation. Otherwise a temporary snapshot could cause valid source history to be deleted just to offset the extra operation copy. Physical disk reporting still includes temporary files. The history budget is not a hard cap on peak disk usage; imports/exports need additional free space. Full wipe inventories abandoned staging files alongside retained/orphan media after active reservations finish.

Backup and Markdown output remain explicitly unencrypted exports in the user-selected destination. Restore's input/inspection scratch now stays in the chosen destination's parent. Backup creation uses source-library scratch for its internal inspection. Standalone backup inspection and standalone CLI transcription/diarization retain their existing temporary-directory behavior when no workspace context is supplied. Cleanup does not guess which library owns old global temporary jobs.

## Remaining encrypted-vault requirements

A small isolated native AES-256 APFS sparsebundle proof verifies create, wrong-password refusal, remount and busy-detach refusal. It is a capability proof, not product acceptance. The app still needs a managed-root registry that fails closed when unmounted, verified volume identity, user-directed unlock, Keychain/biometric integration, full service shutdown, explicit close across every client, busy-volume reporting and migration/recovery UX. SQLite disk-backed temporary tables/sorts require a separate strategy before claiming all plaintext remains on an encrypted volume. External exports and earlier plaintext libraries also need explicit handling. No Keychain item or normal capture library was modified for this proof.

## Validation status

The schema-16 integrated prototype passed **486 tests: 480 pass, six explicit opt-in skips**. Schema-17 validation follows the writer-guard change. Focused ThreadSanitizer passes **80 tests: 79 pass, one opt-in skip**. Fourteen new workspace contracts cover containment/cleanup, private audio/video workspaces, close/wipe waiting without blocking reads, busy-statement retry, closed-store rejection, staging-aware retention, foreign/released leases, parent substitution, redirected library aliases, symlink refusal and Whisper success/cancellation cleanup. Five source-bounding contracts also pass.

The [targeted natural recovery report](../benchmarks/audio-source-recovery-v1.json) verifies all 17 unique clips that failed the original frozen Whisper integration: one attempt each, valid bounds, actual SQLite record and no retained raw audio or leftover staging. This debug integration runner includes both repairs; it is not a new unseen or corpus-wide quality result. Debug backup and Markdown process tests pass, including actual SIGINT/SIGKILL and separate source/destination staging cleanup. Frozen natural measurements and final hashes finished before any local Swift build began. Signed release/process validation follows. Native UI, vault lock and encryption acceptance remain open.
