What OSwind needs to win

One coherent capture and recall loop

  • Capture: Accessibility text first where useful, dependable window/display pixels, microphone and system audio, explicit pause, privacy exclusions and recovery after sleep or missing hardware.
  • Retrieval: exact and semantic search, visual recall, time/app/source/entity scope, source-grounded answers and durable links back to the original evidence.
  • Useful actions: briefs, meeting context, recaps, deliberate drafts, voice entry, workflows and reviewed external-tool use.

Local operation with verifiable limits

  • Models: explicit local/BYOK routing, hardware-fit setup, role-specific endpoints, finite residency and user-visible downloads. Apple/GPU availability is separate from measured acceleration.
  • Data: encrypted storage, safe lock/unlock, migration, export, selective erasure, retained evidence integrity and a complete multi-device lifecycle.
  • Performance: measured workday CPU/RSS, capture latency, storage growth, retrieval quality and energy, using identical workloads and disclosed gaps.

OSwind’s default answer provider is evidence-only. A configured model is a separate choice. Existing local Metal retrieval, Apple-native speech/model paths and Ollama support must be evaluated at their actual operation boundaries; a model’s reported GPU residency does not prove GPU work or battery efficiency.
