The transition needs a separately committed native preparation/fence before private membership handover. A merely cached native checkpoint is insufficient: an already-open native35 connection can retain its old matching SQL proof after an ambiguous external-first commit. Preparation must retain old membership while durably fencing old writers and saving exact recovery intent. Private pairing/delivery authority can advance only after that fence is proven committed. Recovery must preserve legitimate raw local changes made before the fence; it must never repair an ambiguity by replacing device credentials or silently discarding queued work. Native36 compatibility, all writer guards and restricted recovery must be designed and tested together; no schema bump is implemented in this first protocol step.
