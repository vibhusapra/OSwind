# Original-version selective erasure

Schema27 component on `codex/historical-erasure-scope`, based on PR #104 and its explicit-CASE guard repair. The [qualification receipt](../benchmarks/historical-erasure-v1.json) passes all 21 full/sanitizer/optimized, staged-package/process and independent archive stages over 667 identical repository inputs. The overall v0 remains incomplete; feature-status totals and F059 remain unchanged.

The retained schema-26 regression demonstrates an actual omission: an old Safari original remains after its owner becomes a newer Notes source. App, bundle ID, domain, kind, time and their intersection all miss that version when selection starts only from current-owner fields. The first owned test executes one case across six selectors and records 42 assertion failures with no unexpected errors.

Schema 27 selects current sources and archived versions independently. All selector fields must match the same version. A matched original removes that exact archived version, dependent historical recaps, linked canonical recaps and cited turns; it preserves an unrelated newer owner and sibling versions. Deleting the owner still removes all its originals. Tokens bind the scope, current source state, historical revision and selected handles, and selection is recomputed in the deletion transaction.

The native preview reports current sources, original versions, direct original matches, dependent answers and media references separately. Original samples show their recorded app, title and timestamp. Historical-only matches remain actionable when no current source matches. Old preview/result JSON decodes missing original counters as zero. Deletion previews validate the original's own typed body and hash without requiring playable files or a complete parent DAG, so a damaged recap parent does not prevent erasure.

Erasing an archive-selected version also removes its exact typed sync-cache body, cached original projection and transitive cached dependents. Content-free local version revocations survive reopen and reject exact-version reads, re-adoption and new cached records that directly cite an erased version. An independently retained regression first records seven failures: old and dependent cached bodies remain readable and can be re-admitted. The fix preserves the unrelated current owner and its current cached version. This is a local barrier for archive-selected versions; complete incoming policy, cache-only scope selection and cross-device erasure epochs remain unfinished.

Six SQLite-maintained expression indexes cover original start/end dates, app, bundle, kind and URL. They index immutable typed bodies rather than maintaining an editable duplicate scope table. Independent start/end range queries avoid an observed SQLite planner body-table scan for the original three-way overlap expression. Domain-only filtering scans the covering URL index and uses the same Foundation host/IDNA boundaries as current-source erasure. Query-plan and bytecode tests check that domain filtering does not read the source-body column.

Direct source deletion, age retention and storage trimming share the mixed canonical/historical dependency closure. Storage batches contain at most 16 roots and stop at a change between original/current root kinds, allowing the next disk measurement before removing a newer other-kind root. Age retention keeps its existing start-time policy. Historical media enters the existing durable cleanup queue; a remaining canonical or historical reference retains the shared file. Unsafe symlink targets remain untouched and pending cleanup is reported. Whole wipe and result aggregation preserve original-version removal counts.

The new compatibility marker fences canonical and archival writes from already-open older connections, including an empty legacy DELETE. Fresh older executables are fenced by schema 27. Real old26 SQLite and complete backup fixtures are generated by the actual pinned schema-26 product, with hashes/provenance in the test-only resource folder. Migration validates original body integrity, adds compiled indexes/guards atomically, preserves source bodies/citation bindings/capture state, and refuses missing current protection. No SQL from an archive is executed.
