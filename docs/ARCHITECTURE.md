# Architecture

Swift package targets:

- `OSwindCore`: durable store, privacy policy, embeddings/retrieval, model adapters, screen/audio capture, API and MCP protocol.
- `OSwind`: SwiftUI app, AppKit menu/shortcut integration, setup/settings, source browsing.
- `OSwindCLI`: `oswindctl`, diagnostics, imports, benchmark, API/MCP host.
- `CSQLite`: system sqlite3 shim only. USearch 2.26.5 and resolved NumKong 7.8.5 supply the optional native HNSW graph; original source vectors remain in SQLite.

## Screen ingest

Foreground context → lock/idle/secure-field/app/title/URL checks → ScreenCaptureKit focused-window snapshot → small grayscale change signature → off-main Vision OCR → combine bounded Accessibility text → sanitize → suppress raw image if any text/title/URL was redacted → local embeddings → SQLite insert/FTS trigger → UI refresh.

One capture can be in flight. Pause/lock increments a generation token; in-flight work checks it before insert and deletes its image on cancellation. Full-display mode filters excluded apps and all browsers. Redaction is not a comprehensive DLP model. OS permission and URL extraction behavior need live testing per supported browser.

## Retrieval

Keyword queries are tokenized into quoted FTS terms (no raw SQL/FTS syntax). Date/app/kind/favorites/tag filters are SQL-bound parameters. Semantic search reads same-model, same-dimension vectors, computes Accelerate cosine scores and applies a minimum similarity. Apple Hybrid uses reciprocal-rank fusion (k=60). Optional Ollama embedding search uses cosine plus a bounded lexical-coverage bonus, preserving strong cross-language matches. Its Qwen3 query prefix follows the publisher instruction format. The Exact path is a linear vector scan. A precomputed query norm and direct SQLite-buffer scoring avoid per-vector copies. A bounded min heap retains only max(limit, 100) candidates, with deterministic score/time/ID ties. Updated per-model vectors take precedence over legacy same-model vectors. Automatic chooses the indexed path only for unfiltered archives with at least 20k vectors; all filtered queries remain exact after native predicate callbacks measured slower. Explicit Indexed can force approximate retrieval. Cold preparation, counts/statistics, write contention and million-record performance remain gates.

Schema 4 adds stable AUTOINCREMENT vector keys, per-model revisions, a mutation journal and store identity. Source/vector triggers cover legacy and multi-model writes. HNSW uses normalized float16 cosine vectors (connectivity 32, add expansion 128, search expansion 8192). Unpublished construction uses at most four CPU workers. The graph is a disposable cache, not a second evidence archive. Each query checks live SQL scope, source revision and model identity, reranks float32 candidates, and searches newer mutations exactly; excessive delta or unavailable cache falls back explicitly to exhaustive search. This protects source erasure while retaining approximate neighbor selection. A small recent-source sample improves ties; it does not guarantee globally exact approximate ranking.

Cache manifests bind store/model/dimensions/native format, sequence, count and SHA256 to immutable graph files. Directories are 0700, files 0600, symlinks rejected. A kernel lease prevents duplicate cross-process builders. Atomic manifests publish only a synchronized graph; corrupt/incompatible snapshots rebuild. Short read snapshots avoid holding a long WAL reader during construction. Manual cancellation pauses automatic construction; source vectors remain, partial graph construction restarts. Low-power/thermal gates defer building. Idle five-minute maintenance checkpoints only changed graphs, with power policy. Cache eviction precedes source pruning; Delete all clears files and rotates identity. Cache data is not application-vault encrypted. Hard-kill orphan cleanup, restore/fork lineage and cold-load tails remain release gates.

Memory JSON payloads store source metadata; embeddings are separate float32 blobs. Schema 2 adds a multi-model vector table keyed by memory ID and model identity (name, digest, preprocessing version and dimensions). Existing Apple vectors remain readable without reprocessing. Metadata edits preserve vectors; content changes invalidate the extra indexes. Network inference occurs outside SQLite locks, and batch saves compare content hashes to avoid storing stale results or resurrecting deleted records. Resumable 16-record batches retain completed work on cancellation. Automatic indexing is bounded and defers under low-power policy.

`RetrievalEngine` supplies one async search path to UI, Ask, CLI, HTTP and MCP, including coverage and fallback warnings. Keyword queries require no model server. Hybrid falls back explicitly to keyword search on model failure; semantic-only reports the failure. Local model URLs are loopback-only, redirects are refused and known remote/cloud model aliases are rejected before evidence is sent. These checks assume a trusted local daemon. OSwind-managed Ollama servers set `OLLAMA_NO_CLOUD=1`; an existing user daemon is not replaced or reconfigured.

Model discovery, streaming pulls, cancellation and GPU memory residency use Ollama APIs. Local generation and retrieval select independent models. The model manager starts an installed runtime; dependency installation remains in the setup script. No weights are bundled in Git.  SQLite WAL handles external readers. A process-local recursive lock serializes store operations. JSON imports run in a transaction, strip media paths, apply exclusions/redaction and rebuild vectors. Media paths reject traversal and symlink components and must live under `images/`, `audio/` or `video/`.

## Audio

Microphone AVAudioEngine → bounded AVAudioConverter → 16 kHz mono sink. Each system-audio stream owns a separate output/delegate and sink, validating exact PCM layout before copying. Per source: one partial 30-second segment, three waiting full segments and one scheduled actor delivery; the shared ASR queue adds three waiting chunks and one active operation. Capacity drops report lost seconds independently of transcript status. Explicit finish synchronously transfers eligible pending/final input; privacy Pause discards it. Whisper.cpp has a subprocess time limit; resident Parakeet uses configured native compute units. Raw chunks use private leased workspaces and are removed after processing. See [ingress limits](AUDIO-INGRESS.md) and [privacy lifecycle](AUDIO-PRIVACY.md). Actual device/route recovery, callbacks under physical load, background-tab isolation and energy remain acceptance gates.

## Answers

Query + date/app filters → up to 12 evidence memories → query-anchored bounded text excerpts → evidence-only, Apple FoundationModels, local Ollama, or explicit remote BYOK. Prompt separates untrusted source text and requests citations. Source cards are authoritative evidence; model prose must be checked. No agent tools or external writes are available to the answer engine. Full text/context hashes replace prefix-based duplicate suppression, preserving different decisions after shared boilerplate. Lexical windows favor rare query terms; a second passage can cover a distant term. Excerpts preserve composed Unicode, mark omissions, and remain bounded. Recaps/unanchored queries preserve opening and ending text. This does not solve semantic retrieval of a long source whose relevant tail was outside the embedding input. Chunked source vectors remain a separate gate.

Answer prompts keep only the current question and fresh evidence; recent user questions remain retrieval context. Apple uses guided claims in one request. A source-by-source experiment was discarded after generating a wrong owner despite valid citation numbers. Provider output-limit stop reasons fail before chat append. Plain explicit abstention can omit a citation. The setup preset pins Qwen3 Instruct 2507 Q4_K_M rather than a drifting short alias; observed latency/quality and failures are recorded in the benchmark ledger. Local Ollama requests do not read BYOK Keychain accounts.

## Saved conversations

Schema-3 sessions and turns live in the same SQLite database. Turn payloads contain the sanitized question/answer, warnings, provider, timing and explicit filter scope. Separate foreign-key links retain source IDs and citation order; source text is hydrated from the current memory row. Atomic append validates source text/context hashes plus timestamp/kind and session existence, preventing in-flight answers from reviving deleted/revised evidence or sessions. Source deletion/revision, including date/kind changes, removes citing turns and resets associated session titles. Retention deletes aged turns; Delete all clears sessions as well. Independent manual notes, clipboard copies and exports remain the user's separate copies.

Follow-ups use up to three recent user questions for subject context; retrieval includes the two most recent bounded questions plus the current question. Generation receives the current question and source excerpts; earlier questions affect retrieval/excerpt selection only. Earlier model prose is not evidence. Explicit current filters still apply, and the saved scope is shown per turn. App and CLI share this behavior; the HTTP/MCP interfaces remain memory-only. Apple uses [guided generation](https://developer.apple.com/documentation/foundationmodels/generating-swift-data-structures-with-guided-generation) for claims with source-number lists, rendered only after range validation. Other model prose gets citation warnings. Neither structural citation checking nor one successful follow-up demonstrates semantic grounding or broad abstention.

## Release risks

Current store schema is version 20. Later migrations add full-library wipe/media admission, leased workspaces, encrypted libraries, visual retrieval and a crop-compatibility fence; tag metadata is a repairable derived cache within schema20. Preservation and actual pinned older-client refusal fixtures cover the corresponding transitions. Older binaries refuse the upgraded schema. Newer unknown schemas fail without downgrading. Future schema changes require migrations and fixture coverage. App binaries are locally ad-hoc signed, with no notarization/update service. Apple English sentence embeddings remain the default zero-download baseline. Optional Qwen3 multilingual results are measured on a small authored fixture; diverse desktop multimodal relevance and robust no-evidence abstention remain acceptance gaps. Long-run power, pressure, permission revocation, audio hardware changes, and adversarial privacy testing require broader validation.


## Metadata and UI publication

Schema 5 maintains source totals, screen/audio/built-in-vector counts and per-application counts in source-transaction triggers. Timestamp extrema use the existing timestamp index. All app/CLI store connections share the same counters; insert/upsert/delete, import rollback and cross-connection writes are tested against independent full SQL scans. Missing/inconsistent derived totals repair on reopen without changing sources or native cache identity. The one-time migration backfills counters. Favorite/tag-only metadata edits no longer rewrite FTS; title/app/text changes still update it.

`stats(includeDiskUsage:false)` returns a short consistent SQL snapshot. Full storage enumeration happens outside the store lock. The app publishes search hits independently of statistics, coalesces count refreshes and measures storage in a separate task at most every 30 seconds. It shows an unknown/measuring state and last-check time; deletes/import/maintenance invalidate the storage estimate. Generation tokens discard a traversal started before invalidation. The built-in-vector count is labeled Apple vectors, rather than implying coverage of every optional model. Storage traversal and pruning have separate correctness/latency costs; this does not prove media-heavy or sustained UI performance.


## Metal candidate backend and scope reuse

The cache chooses a backend by global model size and hardware budget, not the currently selected scope count. From 20k vectors, supported unified-memory Macs can use an exhaustive float32 MPS matrix/vector product; smaller or unsupported configurations retain the native HNSW engine. Each backend has a separate format-derived manifest prefix and file extension. Metal vectors are normalized in shared buffers, keys map to reusable slots, removal zeros the row and replay replaces changed vectors. CPU selection keeps a bounded candidate heap; SQLite originals are then reranked and revalidated in the same search snapshot. This avoids HNSW's measured million-row random-vector recall loss on the current trials, at a higher RAM cost. It does not guarantee arbitrary floating-point near-tie ordering or language relevance.

Allocation is limited to the minimum of 8 GiB, one quarter of physical memory, one quarter of Metal's recommended working set and maximum buffer length. Growth accounts for simultaneous old/new buffers. Cache I/O is chunked and cancellable, headers/lengths/dimensions/keys are validated, and existing atomic manifests/checksums/private permissions/identity leases remain in force. GPU failure, memory pressure at allocation, excessive deltas and unavailable devices retain exact fallback. Actual live GPU allocations may still fail below the static estimate; this is handled as a fallback, not a completeness claim. Low-power/thermal policy still gates cache preparation and replay.

An additive schema-5 table stores a random 128-bit scope nonce maintained by source-transaction triggers for insertion, deletion and app/kind/date/favorite/payload edits. It is read inside the search snapshot. Up to four recent Metal scope key sets, with at most two million stored keys in total, can be reused only when store/model/vector sequence/nonce/predicate/values agree. Old revisions are discarded; exact per-candidate SQL validation remains mandatory. Up to four coverage-count scopes are similarly cached for real retrieval. Existing schema-5 writers keep the new triggers and therefore invalidate masks when they edit the data. The nonce is rebuildable metadata; this does not solve divergent copied-database/cache lineage. First scope construction, source churn and large arbitrary tag/date combinations still need performance work. Automatic scoped search remains exact until broader performance gates pass.


## Resolved query scope

`QueryScopeResolver` extracts supported capture-time/operator clauses without a model or network call. Calendar arithmetic uses a Gregorian calendar in the request's local time zone, Monday week starts and wall-clock boundaries across DST. Absolute date controls intersect query ranges; app/kind/tag conflicts and empty date intersections throw before retrieval's model-failure fallback. Quotes, code/path-like words and URLs remain content. `MemoryStore.resolveQueryScope` resolves app names in one SQLite snapshot; exact names win, otherwise bounded Unicode folding detects ambiguity. No app-name guess broadens a query.

`RetrievalResult.resolution` is optional metadata. UI controls preview/remove original UTF-16 clause ranges, support literal interpretation and display the resolved date/app scope. `AnswerEngine` resolves only the current question and then disables interpretation of concatenated historical questions. It supplies resolved temporal context to generation. `appendChatTurn` stores the answer's actual filter and time zone, not an old UI filter. Stored payloads add only an optional time-zone field; raw query-resolution copies are not persisted, and returned originals are sanitized. Legacy payloads decode without new metadata.

HTTP search uses form-style percent encoding, including raw `+` as space and `%2B` as literal plus. Unknown/duplicate parameters and wrong types fail explicitly; ISO date validity is checked before model or keyword fallback. The CLI rejects invalid mode/provider selection and exposes literal mode plus detailed resolution. Standalone evaluation is routed before general store initialization so it cannot migrate/open the normal capture archive accidentally.

Public ISO date coding retains representable fractional values and uses a value-type parser rather than millisecond-truncating formatter parsing. Text imports accept precise ISO values and legacy numeric dates; stored chat payloads retain the existing numeric coding. SQLite text parameters and string columns use explicit UTF-8 byte lengths, preserving embedded NUL data and preventing application-prefix scope matches.


## Full-source semantic passages

Schema 6 extends each stable vector key with an ordinal: zero is the existing source vector, positive ordinals are derived passages. Migration preserves existing keys, journal sequence and the AUTOINCREMENT high-water mark even when its last rows were deleted; source/chat payloads and FTS remain intact. Store identity rotates and both cache formats change, preventing pre-passage writers from publishing a base-only cache that a new reader could accept. Native graphs are disposable and must be rebuilt once.

Records over 2,400 UTF-16 units receive 1,200-character windows with 200-character overlap and bounded title/app/URL context. Swift character boundaries preserve composed Unicode sequences, every source character is covered, and there is no passage-count cutoff. Source anchors are validated UTF-16 ranges into the original text. Embedding calls use batches of eight; a complete source is committed with a source-hash check and a manifest/version in one savepoint. Cancellation or power deferral preserves earlier completed sources and retries the interrupted source. This is source-level resumability, not partial passage-level resume for a million-character record.

Apple capture/import and optional local Ollama indexing both create passages. Models settings and CLI `reindex --provider apple|ollama` can backfill archives. Automatic catch-up checks passage backlog as well as base coverage. Power policy can defer additional background passage work. Text remains available to keyword search, and retrieval warns about unfinished long-source indexing. Conservative UTF-8 eligibility may temporarily count a short multibyte record until its empty completion manifest is written.

Exact scoring and SQL reranking keep the best passage per source in a bounded heap. Metal's candidate heap groups by numeric parent key before its cutoff, and its persisted parent mapping has a separate format. HNSW uses bounded overfetch and falls back to exhaustive search when returned passage keys do not provide enough distinct sources; arbitrary approximate-neighbor recall is still not guaranteed. Maintained entity counts select backend size, while maintained parent counts describe memory coverage, avoiding a full registry count on each keystroke.

Search hits carry an optional passage range. Ask, cards, the source inspector, saved chats and HTTP/MCP use this anchor; older hits and chats without it remain readable. Source edits, primary-vector removal, incompatible dimension replacement and deletion invalidate derived passages and manifests transactionally. Saved turns still require the current evidence hash and are erased when their source changes. Opening a full source remains available when a bounded semantic passage misses the answer. No model's source selection or generated answer is thereby proven correct.


The bounded recent-source sample pins its time/app-time scan and a parent/model/revision covering index. Join order alone did not prevent SQLite from selecting a global model/revision range for every parent. A regression checks actual VM-step/full-scan work on 1,500 records rather than relying on latency thresholds or matching plan text. Two failed million-row attempts and the corrected run are retained in the benchmark ledger.


## Portable libraries

`LibraryBackup` uses a pinned WAL snapshot plus descriptor-relative APFS clone/streaming media pins outside the live root. Bounded NDJSON manifests are indexed in private SQLite scratch files; packages publish via atomic no-replace rename. Each scratch payload has a sibling private marker and flock lease for conservative abandoned-job cleanup.

`LibraryBackup.restore` reads ordinary known archive tables with trusted-schema/query-only settings and bounded records, then rebuilds a fresh compiled schema. It preserves source/chat/vector/passages, remaps assets, and derives registry/counters/identity. Archived triggers, views, indexes and control metadata never enter the restored library. Restore integrity checks and explicit connection close precede publication. Source and destination stay separate; live in-place replacement is unsupported.

`AppSession` owns the selected `AppModel`, handles unavailable saved locations with recovery, and opens a restored library after validation. Restored services/remote inference and automatic retention cleanup are disabled. CLI inspect/restore dispatch before normal store initialization. See [backup workflow and limits](BACKUP.md).


## Audio source preservation

`SpeechTranscript` stores validated segments, duration and model provenance; audio memories optionally carry a session ID. `AudioAdmission` sanitizes full/segment text, suppresses whole-clip retention on detected secrets, copies only into newly owned paths, and removes that copy if database insertion fails. The original import is never moved/deleted. Source text must match structured transcript text at admission, including JSON interchange and restore.

`AudioClipSnapshot` protects imported bytes with COW/streaming pins. `AudioNormalization` incrementally decodes/downmixes/resamples to a private 16 kHz PCM WAV. Import and live transcription use private leased workspaces, separate from storage-budget traversal. Additional indexing is a post-save operation. The native player controls use the original retained file; source deletion and view/library changes stop playback. See [workflow and remaining gates](AUDIO.md).


Imported speaker recognition uses an independent FIFO actor and exact local Community-1 models. The SDK's downloading/recovery loaders are deliberately not called; model setup is separate and pinned. Speaker turns become anonymous recording-local labels through prefix-duration coverage indexes. Structured diarization metadata records model, scope, detected count and unassigned span count; schema 9 prevents old writers discarding it. No embedding/profile vectors are serialized. Manual recording-local renaming holds a SQLite write transaction and validates labels before rewriting metadata.


Native model installation has no source-checkout/Python dependency. Reviewed JSON catalogs compile into Core via a deterministic generator checked in CI. A credential-free ephemeral URLSession streams each HTTPS body into an owned descriptor in a private leased workspace; byte limits apply before writes, then bounded SHA-256 verification precedes atomic no-replace publication. Existing installs are read/verified, with unexpected model components refused. Trusted cache-parent aliases are pinned by identity; path moves/redirection fail, and model caches cannot be nested in live libraries, backups or managed model packages. The native-model CLI dispatches before ordinary library creation. UI completion snapshots preserve manual settings changes and defer selection during audio/import work; library switching cancels the old context.


## Sampled visual replay

Schema 12 adds optional timed visual metadata and an owned video path to screen memories. `ReplayCaptureSession` binds a focused window, applies privacy/context checks around local Vision OCR and uses one consumer with a newest-one-frame buffer. `VisualChunkRecorder` serializes append, flush and close across actor suspension; each short clip owns its HEVC video and thumbnail. Native AVFoundation playback can seek from a literal passage to its OCR frame and show that frame's boxes. Frame times annotate answer evidence without replacing source text offsets.

Normal pause drains already admitted work. Privacy/settings/library/erasure boundaries invalidate a shared publication gate before private media can be copied and indexed; rejected copies/rows are cleaned up. Stream failures propagate through the throwing frame sequence, update error metrics and cause bounded CLI capture to fail. VideoToolbox hardware requirements, encoder readiness/finalization timeouts and power/thermal sampling backoff bound work. Full backups include video; JSON import strips media references. Force quit can lose an uncommitted clip. All-display replay, natural-workload/energy/device-recovery acceptance and cross-clip scrubbing remain open; see [the replay protocol](REPLAY.md).


## Activity calendar

`MemoryStore.activityCalendar` constructs Gregorian civil day/hour UTC intervals, including repeated/skipped dates and partial-hour transitions. One bounded CTE statement aggregates all requested buckets under a single SQLite read snapshot. Covering timestamp/application/kind indexes and a partial saved-time index serve common metadata scopes; tag membership and its duplicated metadata use a transactionally maintained covering projection. No inference, retained media or full-source hydration is needed. Schema20 stays unchanged; the two extra indexes are derived and maintained by ordinary SQLite writes.

`ActivityCalendarModel` owns utility tasks, generations, cancellation and a visible/active/unlocked revision monitor. It coalesces capture notifications, clears counts for destructive/library boundaries and rejects stale replies. Day/hour navigation copies exact UTC bounds and metadata into the native search scope, with a visible calendar slice and fail-closed missing intervals. The same core aggregation serves the CLI, authenticated loopback HTTP and read-only MCP. See [calendar semantics and acceptance gates](ACTIVITY-CALENDAR.md).


`TagIndexSchema` backfills exact string membership and metadata in the opening transaction, with SQLite progress cancellation, readiness/trigger validation and repair. SQL triggers preserve schema20 older-writer coherence. Restore ignores this derived table and rebuilds from sources. Native `AppSession` constructs the store on a utility worker, then validates its selected directory before creating a model. Cancel/termination/lock reject and close late results; ordinary and managed close retain the original directory lease. See [tag index consistency, costs and opening lifecycle](TAG-INDEX.md).


## Shared Accessibility observations and live audio

`AccessibilityContextCoordinator` shares one in-flight same-PID/bundle read across at most eight consumers, with independent cancellation leases. It keeps the shared worker occupied until actual completion and never reuses completed results. All native AX attribute IPC is within the bounded utility traversal; the former synchronous helper is now async.

`AudioController` renews context at startup boundaries, through one poll job, before WAV creation and after ASR. Epoch/session ownership is captured with each queued chunk. Stop/source/privacy changes cancel the current context session, while old replies cannot affect a new run. Directory identity is rechecked before file work and admission. Recognition errors retain allowed capture; privacy errors stop it. See [lifecycle limits and evidence](AUDIO-PRIVACY.md).
